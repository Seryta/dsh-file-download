# 文件下载

在右侧预览面板里保存文件本体，补上「能看、但下不下来」的缺口。

## 提供两个入口

- **预览标题栏的下载按钮**：位置在预览面板标题栏里、文件路径右侧、面板自带控件（换行 / 自动刷新 / 重新读取）之后。只要面板拿到了宿主上的真实路径，文本、图片、PDF 乃至无法渲染的二进制包（`.apk`、`.zip`、`.ipa`、`.deb`…）都能点。
- **空状态里的「下载文件」按钮**：当文件连文本预览都读不出来（`not-text`、`too-large`，或已知的二进制容器），空状态里会在原有「打开」下方另起一行，多一个主按钮。

## 保存方式

点击时**同步**把下载地址交给浏览器（中间没有任何 `await`），所以移动端浏览器（Chrome / Via / Safari）会把它当成用户手势发起的下载，交给系统下载管理器，进度条和断点续传都在系统里。

下载走本插件宿主半部提供的鉴权路由 `GET /api/file-download?path=<绝对路径>`：

- 响应带 `Content-Disposition: attachment`、正确的 `Content-Length` 与媒体类型（`.apk` 是 `application/vnd.android.package-archive`），文件名含中文时附带 RFC 5987 形式；
- 正文是 `ReadableStream`，按 4 MiB 窗口通过宿主文件系统逐段读取并回压输出，**宿主内存不随文件大小增长**，也没有单文件大小上限（不受 `/api/file` 的图片字节上限约束）；
- 支持 `Range` 请求，返回 `206` 与 `Content-Range`；同时给每个文件版本一个强 `ETag`（版本与大小的 sha1 摘要，
  不暴露路径元数据），并在续传时按 `If-Range` 校验：校验器一致 → `206` 只发剩余字节；文件已变 → 退回 `200` 发整份。
  Chrome/Edge 的分段下载（实测 8 路并行）与系统下载管理器的「暂停/继续」都依赖这个校验器。
- **一个响应只含一个文件版本**：首个窗口在写响应头之前读取，读不出来就直接回答 `403`/`404`，而不是先给一个会死在半途的 `200`；
  其余每个窗口在入流前复核文件版本，下载期间文件被替换即中止响应，绝不把两个版本拼进同一个 200。

页面若在宿主半部挂载前就已加载（该路由尚未注册），会自动退回官方 `/api/file` 路由。该兜底单次缓冲、受宿主图片上限（默认 50 MiB）约束，**超过上限会得到 `413`**，所以超大文件需要刷新页面让探测重跑一次、用上流式路由。

## 已知边界

- 只面向 Web（`platform: web`）；桌面端的「另存为」仍由官方 `ui-file-actions` 负责，本插件不接管。
- 预览标题栏原有能力没变：右键文件路径的菜单里本来就有「下载」，本插件只是把它变成一眼可见的按钮。
- 保存的文件名取宿主路径的最后一段；同名文件由浏览器自行加序号。
- 宿主重启后需要刷新页面，才能让已打开的页面重新探测到流式路由。
- 后端不报文件大小时（非本地文件系统的自定义后端）不声明 `Content-Length`、不提供 Range，因此不支持续传。
- 下载中途文件被替换时响应会被中止（用户看到下载失败），重试即可；不会产出混合文件。
- 若前置反向代理不把上游断连传播给客户端，中途失败会表现为客户端挂到自己的超时——属代理侧缺陷，插件不能代偿。

## 反向代理要求

下载路由已自带 `X-Accel-Buffering: no`，nginx 会按这个响应头关掉该响应的缓冲，所以 nginx 侧**不强制**要改配置。

若代理层用的是别的实现（Caddy / Traefik / HAProxy），或希望整站更稳，建议在 dsh 的 location / server 上加：

```nginx
proxy_buffering off;            # 或依赖响应头；开启时 nginx 会把大文件写到自身上临时文件
proxy_max_temp_file_size 0;     # 兜底：禁止临时文件缓冲
proxy_read_timeout 3600s;       # 手机锁屏/切后台导致上游停顿，别 60s 就掐断
proxy_send_timeout 3600s;       # 慢客户端侧同理
```

`Range` 由 nginx 默认透传，`Content-Disposition` 不在默认 `proxy_hide_header` 名单里，两者都不需要额外处理；`gzip_types` 未包含二进制类型，也不会被压缩。
