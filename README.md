# dsh-file-download

在 DeepSeek Harness Web 的右侧预览面板里，直接下载当前文件。要求 **DSH 0.2.2-rc.3 或更新的 0.2.x**；Desktop 中检测到 `window.dshDesktop` 后不注册本插件的入口，原生保存仍交给官方文件动作。

| 入口 | 位置 |
|---|---|
| 下载图标 | 预览标题栏，文件路径右侧，面板自带控件之后 |
| 「下载文件」按钮 | 无法预览的空状态，原有「打开」下方 |

两个入口使用面板提供的宿主绝对路径，支持文本、图片、PDF 以及 `.apk`、`.zip`、`.ipa`、`.deb` 等无法预览的二进制文件。

## 下载链路

点击时同步创建 `<a download>`，交给浏览器或系统下载管理器；点击路径没有 `await`，页面不缓冲完整文件。

```text
点击 → GET /api/file-download?path=<绝对路径> → 系统下载管理器
```

官方 `/api/file` 会先读完整文件，受宿主图片字节上限约束（默认 50 MiB），且不提供本插件的 ETag/If-Range 续传校验。本插件按 4 MiB 窗口流式输出，没有单文件大小上限，内存用量随并发数变化，不随文件大小增长。

| 方面 | 行为 |
|---|---|
| 响应头 | attachment、ASCII 文件名兜底和 RFC 5987 UTF-8 文件名、媒体类型、`ETag`、`X-Accel-Buffering: no`、`X-DSH-File-Download: 1` |
| 已知大小 | `Content-Length`、`Accept-Ranges: bytes`，单段及后缀 Range 返回 `206`；不可满足返回 `416` |
| 续传 | 匹配 `If-Range` 才发范围；陈旧、日期或弱校验器退回 `200` 整份 |
| 未知大小 | 不声明长度、不提供 Range；静态文件仍按窗口输出，EOF 也检查版本 |
| 首窗失败 | 首窗读取和校验在成功响应之前完成，有、无大小分支统一映射错误 |
| 错误 | 400 路径非法；403 权限或非普通文件；404 不存在；409 首窗校验发现变化；416 范围不可满足；499 读取取消；其他读取错误 500 |

## 数据一致性与读取权限

宿主共享文件由文件系统的 `processPath` 和 `processPathFromHostPath` 明确确认后，**每个请求只打开一次本地文件句柄**。大小和 ETag 的身份来自实际打开的文件，避免首次 stat 与 open 之间发生换绑时，把旧版本的校验器附到新正文上。文件系统的 opaque version 不被解析，响应头仅发送摘要。

每个窗口仍经 `ctx.fs.readByteRange` 读取，以保留后端自己的访问策略；同时从固定句柄读取相同窗口，两份字节必须一致，并复核句柄元数据及后端版本。目录临时切换后又恢复时，混入另一对象的字节会被拒绝。原地写入导致元数据变化、可见的路径替换、删除、提前 EOF 或读盘失败均会终止传输。**这一校验增加了一次窗口读取及元数据检查，不能沿用旧版本的吞吐量数字。** 两份窗口仍有固定大小，不会把整份文件留在内存中。

完成、首窗失败、空文件、HEAD、416、正文异常、请求断开和消费者取消均释放该请求的句柄。消费者取消也会中止在途的抽象文件系统读取。

**自定义后端的能力边界**：没有宿主路径映射时继续使用 `ctx.fs` 的窗口读取和版本检查，包括 EOF 检查，不尝试在本机打开远端路径。当前 DSH 的抽象接口把 `stat` 与读取分开，没有“返回与指定版本原子绑定的字节”或不可变快照能力。因此插件不能对任意自定义后端证明绝对单版本，固定句柄也不能替代所有文件系统上的不可变快照。需要这种保证的后端必须提供原子版本读取或快照；这项上游能力仍待补齐，不能仅靠重复路径 stat 解决。

## 路由探测与恢复

页面加载后用 HEAD 探测，并要求响应带 `X-DSH-File-Download: 1` 才确认能力；无路径探测正常得到带标记的 `400`。401、403、5xx 或网络错误都表示暂时未知，不当作路由在线。首次请求加最多 3 次自动重试，间隔 1/3/10 秒，每次超时 5 秒；网络 `online` 事件可重新开启探测，卸载时取消请求、计时器和监听器。

未完成探测或状态未知时优先使用流式路由，避免首次点击意外触发官方大小上限。只有确认未标记的 `404` 才退回官方 `/api/file`；该回退仍受默认 50 MiB 上限约束，大文件会收到 `413`。宿主刚安装而路由尚未挂载时，需要先让宿主加载新模块，之后刷新页面或恢复网络以重新探测。

## 安装

```bash
dsh plugin --profile <profile> add <本仓库绝对路径>
```

也可使用 DSH Plugin Manager。启用宿主 `@deepseek-ai/dsh-hmr` 时，profile 重组会比较链接包的已加载文件并替换变化的宿主模块，**无需重启服务**；需要主动应用时，可通过 Plugin Manager 重新应用该已启用插件。应结合操作结果与下载路由探测确认生效，不能只看磁盘上的包版本。未启用 HMR，或操作明确返回 `restart-required` 时，再按其原因处理。客户端使用独立的模块加载机制，必要时刷新页面载入新代码。

## 反向代理

nginx 通常会按 `X-Accel-Buffering: no` 关闭该响应的缓冲。可进一步配置：

```nginx
proxy_buffering off;
proxy_max_temp_file_size 0;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
```

Range 默认透传。正文中途失败时，代理必须把上游异常断连传播给客户端；否则会表现为下载挂起。本部署曾在 Go 门房 v0.5.2 验证断连传播，属于历史部署证据，不代替升级后的链路验收。

## 验证

构建和测试应通过有界容器运行，项目没有依赖安装或独立编译步骤：

```bash
npm test                  # 宿主路由 + 客户端 VM 行为回归
npm run test:mutation     # 10 个宿主行为变异必须被捕获
```

[宿主测试](test/route.test.mjs) 覆盖完整下载和范围字节、续传组装、状态映射、空文件后缀范围、RFC 5987 特殊字符、无大小 EOF、首窗及中途失败、目录回滚、固定句柄字节对照、首次 open 的 ETag 归属、后端权限不被绕过、句柄释放及在途取消。[客户端测试](test/client.test.mjs) 在受控 DOM、fetch、计时器和事件环境中验证两个入口、同步点击、探测标记、有限重试、超时、网络恢复、卸载与 Desktop 排除。

[变异检查](scripts/mutation-check.mjs) 独立破坏取消检查、版本复核、头净化、首窗错误、If-Range、中途 error、固定句柄、字节对照、RFC 5987 编码和 EOF 校验，要求回归测试失败。临时副本正常和异常退出均清理。

这些验证不等于真实浏览器下载管理器、移动端、Windows、Desktop 原生保存、HMR 或公网反向代理的端到端验收。元数据版本检查的强度还取决于后端和文件系统本身；不把未验证能力描述成快照保证。
